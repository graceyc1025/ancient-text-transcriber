# 竖排 OCR 排查、改动与同图对照

验证日期：2026-10-13。基线为已合并的 `e323b56`；改动位于独立分支 `feat/vertical-ocr-diagnostics`，未合并或发布。

## 排查结论

用户反馈电脑、手机都出现整页只显示少数字。尚未取得用户的故障原图、浏览器控制台或实际手机日志，不能断定所有设备上原因相同。

基线已经使用固定版本 tessdata_best 的 **chi_tra_vert**、LSTM 引擎和 **字符串 PSM 5**；横排才用 chi_tra / PSM 6。没有发现误把默认竖排设为横排。Worker、WASM、两个模型均经同源真实浏览器加载；模型文件的解压 SHA-256 校验保留。不是刚把原有语言换成竖排模型。

基线处理流程为全页或人工框选 → 最多2倍放大、最长边2400 → 一次 OCR → 根据检测坐标排序 → 置信度低于65标□。它没有先分竖列、没有可调预处理，且原始输出未留存。整页复杂版面会影响检测；大图缩小可能损失小字细节；排序不能恢复未检测的字。

未核定年代的手写文献扫描 `page_2.png`，基线检测到76个字词框、输出82字符，其中70个被标□，只剩12个可见字。**可见字少、检测字少、错字多是不同问题。** 同一手稿单列、同一裁剪和像素处理，PSM3输出12字，PSM5输出1字，PSM6输出5字，PSM7无输出，表明页面分割影响检测；PSM5不能被当作任意古籍单列的保证。

在 Chromium 中未重现模型缺失或识别中断。真实手机上的内存峰值、系统杀页、Safari兼容性未测定，不能排除这类原因。新增的画布预算限制不等于整个 WASM/浏览器的总内存上限。

## 有针对性的改动

- 像素投影分栏，或指定1–30列均分，右至左逐列真实 OCR。分析缩图最长边1000；仅在测量投影时忽略大片横线，不从识别图像抹去笔画。切线覆盖整个所选区，自动失败退回整区。版框、印章、双行夹注仍会干扰切线，用户应先框正文并检查分析框。
- 每个框选区域有独立识别按钮，及排版、整区/分栏、PSM设置。识别该区仅替换对应结果，保留其他栏人工文字；标题、正文、版心由用户指定，未实现可靠自动分类。
- chi_tra_vert / chi_tra 对照；PSM3/4/5/6/7/11对照。PSM6/7主要用于横排，作为实验选择，不冒充可靠竖排模式。
- 1/1.5/2/3倍、灰度、50–250%对比度、全局 Otsu、局部自适应或手动二值化；可比较原图和缩略预览。默认仍为整页、竖排模型、PSM5、2倍、无灰度/二值化、对比度100%。预处理可能抹淡字，改变设置后旧预览失效，需重新生成。
- 手机/低内存自动预算每次150万像素，标准每次500万；分区/分列独立预算，不再全部限制最长边2400。串行识别、独立小缩略图、临时画布释放。原图解码仍有内存成本；建议手机1–3张开始。
- 显示实际检测框、输出数量、□数量、加载/识别进度；加载120秒、每次识别90秒超时提示。可停止识别并保留已有编辑、已完成记录。模型初始化时库尚不提供句柄，停止可能等待初始化完成或超时，不能保证瞬时释放。
- 每次、每区、每列保留**引擎原始文本、原始TSV、排序后原始文本、标疑底稿、区域坐标、模型/PSM/处理参数、工作图尺寸、检测数量、时间**。人工编辑不修改记录，支持复制和本页全部记录JSON下载。中断可保留已完成列；刷新前必须另行保存。

没有简繁转换、语义纠错、现代标点补全、上下文补字或异体字替换逻辑。引擎本身仍可能误认、增字、错认标点。□只针对已检测的低置信度字词，不假装准确标出所有漏字。

## 功能验证与复现

- 18项单元测试：像素处理、分栏覆盖/空图退回、内存尺寸、漏/错/多识计数、列序、Unicode、模型相对路径、TXT和DOCX。
- 5组真实 Chromium 浏览器测试：Pages项目子路径、JPG/PNG批量、模型识别、图文对照、框选、独立区域编辑保留、原始记录不变、JSON下载、检测框、处理预览、停止、故障后底稿保留、复制、TXT/DOCX附图。
- 其中一组使用390×844触屏手机模拟，并发送真实浏览器触控事件，执行真实 OCR、150万像素预算及编辑导出，检查无页面横向溢出、无第三方请求。**这是模拟测试，不是Android/iPhone实机验证。**
- 本地静态构建与模型校验通过；未据此宣称新版本已上线、云端Actions已通过或所有手机均兼容。

维护者复现（网站使用者不用运行命令）：

```bash
npm ci
npm test
npm run build
npm run test:e2e
npm run test:ocr-comparison -- tests/samples/local/page_2.png tests/samples/local/maoshi.png
```

额外扫描需按上面固定来源自行准备，仅放 `tests/samples/local/`，禁止提交私人文献。没有扫描时比较脚本仍会运行现代图并明确缺失古籍真值。脚本需要本地保有基线提交，可用 OCR_BASE_REF 指定另一已知基线；不要将浅克隆无法取得基线误报成OCR失败。原始结果写入 test-results/，浏览器测试会清除此目录，请先备份需要的比较结果。

## 建议的实际使用步骤

取消自动识别 → 上传1张 → 框正文 → 分析分栏并检查边界 → 对同一框比较PSM5与PSM3，再尝试灰度/二值化 → 看检测框与原始输出 → 逐字校勘。标题、版心另框并独立识别。保留原图、JSON方法记录和最终TXT/Word。

PR检查完成并经拥有者评估后才合并main，随后现有Pages工作流发布。此分支不会自动覆盖已部署版本。实际清代效果须用有版本来源的原图及人工真值继续检验。
