# 双引擎实验版本：使用、实现与验收记录

日期：2026-10-17（北京时间）。代码位于 `experiment/paddleocr-v5-browser`，没有合并 main、修改 Pages 部署工作流或发布正式网站。正式网址仍是原版本，不能在那里验证本次新增功能。

## 如何测试这份实验版本

本轮提供构建好的静态测试包，包含完整 `dist`、所需引擎/模型/许可及版本说明，不含用户古籍图片或人工底本。它需要静态 HTTP(S) 预览；**不能直接双击 index.html 或用 file:// 打开**，否则 Worker、模块和模型读取会受浏览器限制。本轮没有创建可公开访问的实验网址，也没有把正式 Pages 改成实验站。

有现成静态预览环境时，将包内 `site` 作为网站目录即可，无需 OCR 后端、API Key 或 Python。使用者在打开的网页中操作即可；下面是维护者在现有开发环境准备预览的方法，不是正式网站使用者的安装要求：

```bash
git switch experiment/paddleocr-v5-browser
npm ci
npm run build
npm run preview
```

浏览器打开维护者预览环境提供的入口。云端终端的监听地址不自动等于你的电脑或公开地址，须使用所在平台支持的静态/端口预览；没有该能力时测试包本身不会生成网址。本轮不执行任何发布步骤。

1. 先使用电脑浏览器。引擎默认 **Tesseract · 现有引擎**，原有分栏、语言模型、PSM、图像预处理继续可用。
2. 选择 **PaddleOCR · 试用（整页 / 整区）**。只有开始识别时才加载 Paddle，初次需要下载约60MB本站资源，下载期间会显示当前文件、已读MB及该文件百分比；不是上传图片。
3. 上传 JPG / PNG，或先取消自动识别再框选正文。Paddle本阶段仅整页/整区识别，不自动分栏补白；Tesseract分栏保留。Paddle默认1倍，沿用自动内存预算；手机/小视口使用150万工作像素，桌面标准500万。可以手动选择预算和预处理，但这些选择会改变输入，不应继续套用旧基线分数。
4. 右侧显示几何阅读序文字；竖排按右至左、同列上至下。标题、版心、正文可以分别框选、分别识别和编辑。复杂混排、跨列大框、小字夹注仍可能乱序，须人工检查。
5. 在“原始 OCR 输出与识别记录”查看和下载原生文本、重排文字、原始SDK项/坐标/分数、模型/运行时版本和实际工作尺寸。Paddle不按置信度替换为□，不归并繁简或异体，不补字/标点。人工编辑不修改历史原始记录。
6. 点击“停止识别”可硬终止Paddle Worker，不必等当前推理完成。取消或失败后已有底稿保留；Paddle失败会暂停后续页，可切回Tesseract再“转录待处理页”。不会静默切引擎或伪装为空白页。
7. 修改文字，复制、导出TXT或Word；Word可附原图。关闭前导出：本轮没有增加自动草稿持久化，操作系统杀页仍可能使未导出内容丢失。

## 本轮实现

- `src/engines.js`：轻量双引擎协调器，动态导入所选适配器；切换时先取消/释放旧引擎；任务代号使迟到结果失效，不同时初始化两套模型。
- `src/paddle.js`：Paddle适配现有页面/区域/编辑/导出接口。加载超时120秒，单区识别超时90秒，主线程计时和直接 `terminate()`；错误、部分结果及取消单独处理。
- `src/paddle-worker.js`：读取/解码图像、预算缩放、预处理、SDK/OpenCV/ORT及推理均在独立Worker；Blob传入，不从主页面复制整页RGBA。一个任务/一个区域串行执行，画布和ImageBitmap用后释放。
- `src/reading-order.js`：保留实验既有几何规则，无底本/词典/语境介入。没有为两份古籍调整识别算法。
- `scripts/prepare-paddle.mjs`：固定社区模型包、官方字典及SDK Worker，构建时验证权重、tar、字典和Worker哈希；失败中止构建，不使用模拟模型。根包锁纳入依赖，干净 `npm ci` 后可生成静态资源，不依赖忽略目录中的私人模型缓存。

Paddle仍使用官方SDK 0.4.2及此前社区导出的PP-OCRv5 mobile权重，检测/识别tar与既有实验逐字节一致。不能称为与未取得的官方原始tar逐字节相同。所有许可随静态构建复制。

### CSP如何处理

**编辑页的CSP原样保留，未增加 `unsafe-eval`、第三方域名或 blob Worker 许可。** 编辑页只加载约5.5KB Paddle适配器，通过本站普通模块Worker通信；不import整个Paddle SDK或OpenCV。

当前SDK/OpenCV内部动态求值仍存在，但仅在单独的同源Worker中执行：SDK官方预打包Worker由轻量桥接层按固定协议调用，不在编辑页执行。普通同源Worker有自己的执行策略；GitHub Pages未为它设置文档同款CSP，因而这里不是“让OpenCV不再需要eval”，也不是浏览器进程级或不同源的安全沙箱。该设计限制了编辑页的执行面，**没有修改文档CSP来绕过限制**。

桥接层拒绝SDK显式fetch到Paddle目录外的地址及非GET方法，仅允许本站Paddle资源及固定内嵌WASM的数据URL；ORT模块路径也明确同源，完全不走SDK的CDN回退。模型/用户文字不用于生成可执行代码，用户内容继续通过文本DOM/textarea展示。原始SDK存在的执行权限不应被夸大为完整权限隔离。桌面实际通过严格CSP识别且未发生文档CSP违规；未来给Worker增加响应头CSP时，应另做兼容评估，不能假设它在同样禁止eval的策略下仍能工作。

桥接协议是SDK 0.4.2分发的Worker协议，属于版本耦合点：Worker文件SHA-256固定为 `477db3f009c118823a5f9ebe15f1e96c1c464165715ba28a9884290f61addf52`，升级SDK必须重新审查协议，不能直接替换文件或跳过校验。

### ORT/WASM与资源

实际执行路径使用SDK Worker内嵌的ORT **1.24.3** 与同源 **1.24.3** JSEP模块/WASM，根依赖也固定1.24.3、无第二套ORT。配置清单不一致时在模型初始化前拒绝执行。本轮没有混用旧的1.22.0 WASM。

继续WASM单线程、batch=1，不依赖WebGPU、SharedArrayBuffer或COOP/COEP；`crossOriginIsolated=false` 下完成识别。资源路径由文档项目base解析为同源Worker URL，之后在Worker内部按自身URL解析，不依赖 `document` 或域名根 `/models/`。测试静态服务器补齐 `.mjs` MIME；Pages部署配置保留现状。

两份tar共21,572,608字节；SDK Worker、ORT模块/WASM和模型合计57,975,443字节，另加页面小文件及许可，故界面提示约60MB。这是未压缩文件体积，不是GitHub Pages/手机冷下载实测流量；缓存和HTTP压缩可能影响传输。构建只带当前用到的ORT资源，没有复制实验旧版ORT/未用的第二套大包。

## 桌面实际测试结果

环境：Linux桌面Chromium 154.0.8037.57，真实WASM推理；不是Android/iPhone实机。验证记录中的现代演示图仅用于工作流，实际古籍输出回归另列如下。

| 检查 | 本轮结果 |
| --- | --- |
| 冻结依赖安装 `npm ci` | 完成 |
| 静态构建 `npm run build` | 完成，模型/字典/SDK哈希验证通过 |
| 单元测试 | 20项通过 |
| 完整浏览器回归 | 最终完整回归13项通过（46.9秒） |
| 严格CSP、只加载选中引擎 | 真实Paddle及Tesseract完成；未选引擎无模型/运行时下载，全部捕获请求同源GET/HEAD |
| 原有功能 | Tesseract繁体横/竖排、分栏、预处理、分区、批量JPG/PNG、图文对照、复制及TXT/DOCX通过 |
| 新Paddle功能 | 整页、批量、独立分区更新、原始记录、人工修改与TXT/DOCX通过 |
| 异常 | 模型404、版本不一致、下载中取消、永久阻塞Worker硬取消、主线程90秒看门狗、内存错误提示及回切Tesseract通过 |

### 两份真实古籍的输出回归与响应性

每份使用此前同一正文输入、同一500万工作像素预算及冻结整页检测参数，分别冷浏览器连续运行两次。只比较候选，不把人工标准传入引擎、不调参。本轮运行时变为1.24.3，因此实际核对新输出后才判断是否保持基线。

| 样本 | 工作图 | 两次区域耗时 | 浏览器树峰值PSS | 25ms页面心跳最大间隔（两次） | 与冻结候选 |
| --- | --- | --- | --- | --- | --- |
| 民国本《序文一》 | 2522×1982 | 5.236 / 4.398秒 | 964.0MiB | 131.6 / 26.7ms | 原生及几何序两次都逐字一致 |
| 道光本行书页 | 2607×1917 | 2.447 / 1.913秒 | 925.4MiB | 117.8 / 37.4ms | 原生及几何序两次都逐字一致 |

耗时是区域请求、Worker解码/处理/推理及适配记录的用时，不含首次SDK/模型初始化；测试自动化的下载/点击总时另存，不能冒充纯模型耗时。内存以约100ms采样整个Chromium进程树PSS，包含浏览器基线、UI、图像、Worker和WASM，峰值覆盖两次运行及导出原始JSON，不能当作手机内存或模型独占内存。单次观测与先前测试环境/路径不同，**不能据此声称内存下降某个可靠百分比或已经解决低内存手机问题**。

相比旧主线程路径在道光页观测到约2.57秒心跳停顿，本路径在这次回归中没有超过250ms的心跳间隔，说明已把主要同步推理移出编辑页。浏览器调度、初次图片检查、导入/Word生成仍可造成波动，不承诺任何设备永不短暂停顿。

几何序候选SHA-256：民国本 `e4f850ea2081452b669b408fbfbc637b2f8634ea7ba8c15a72275b9963a673ad`；道光本 `113cbee5900e6940e1bbefe6d1e44b871546da4f00e146a44ee68c2275ceb8ce`。对应原有CER分别12.36%、22.50%（后一底本待复核，暂定），本轮没有制造新的准确率提升结论，字表缺项等限制不变。

## 尚未验证及明确限制

- 没有Windows/macOS的Chrome/Edge、Firefox、桌面Safari真机测试，也没有Android/iPhone/iPad真机。桌面Chromium通过不是跨浏览器承诺。
- 尚需Android Chrome与iPhone Safari验证：冷下载/慢网、所需WASM/模块Worker/OffscreenCanvas、实际内存、连续10页、20次引擎切换、后台/锁屏恢复、取消/重试和附图Word导出。
- 低内存设备仍可能被系统直接关闭标签页；此时JS无法保证显示错误。150万预算仅限制工作图，不限制模型固定内存、原图解码缓存或全部进程。此轮没有自动恢复草稿，也没有实机OOM证据，应先导出人工成果。
- 页面图像检查仍先解码再核对像素上限，大量图片导入和Word附图可能造成额外主线程/内存峰值；本轮没有把整个应用改写成全程无解码风险的架构。
- 只两份真实古籍各重复两次，不是长期稳定性或泛化精度验证；Paddle仍会误识繁简/异体、漏字和混排。更换字体、模型或输入预算须另存结果，不能硬编码修字或沿用未测分数。
- 完全免费且无付费OCR/API/后台，仍消耗用户设备和下载流量。GitHub Pages实际HTTPS、资源缓存/MIME及手机网络表现要在以后独立预览/部署验收；本轮没有宣称正式站已更新。
