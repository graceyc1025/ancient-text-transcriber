# 清代古籍同图对照测试（实验分支）

适用分支：`experiment/paddleocr-v5-browser`。这是独立实验工具，不会替换正式网页。本轮没有合并 main、修改正式界面或发布网站。

**样本缺口：仓库没有经过来源核定的清代原书图片与可靠人工标准转录配对数据。** `example.png` 是现代排版演示图；本地未鉴定手稿没有完整标准稿。因此本轮交付的是可操作的测试流程和记录功能，没有清代刻本、异体字或行草准确率结论。需要用户提供原图及逐字校对的 UTF-8 TXT，最好附书名、版本/刊年、卷页号、来源、转录范围、校对者及存疑处。不要把 OCR 候选直接当作标准稿。

## 先在桌面浏览器操作

由维护者按[实验目录说明](../experiments/paddle/README.md#开发者复现)准备资源并构建，然后在 `experiments/paddle` 运行：

```bash
node serve.mjs
```

在桌面 Chromium 打开 `http://127.0.0.1:4180/ancient-text-transcriber/experiments/paddle/`。这是本机静态测试地址，不是已经发布的在线网址。服务只有静态 GET/HEAD，没有上传或服务器识别接口。未来若单独提供静态实验网址，网页使用者可直接上传并运行，无需安装；本轮没有发布该网址。

1. 上传一张 JPG/PNG，输入或导入该图对应的人工标准 TXT。导入只接受有效 UTF-8；不猜测 GBK 编码。图片限制沿用原项目的 20MB、2500 万像素。私有图片无需放进仓库或 public 目录。
2. 填写样本性质、来源和校对者。只有确认标准逐字校对且范围一致后，勾选确认框，结果才计 CER。更改图片或标准会取消确认；已有测试记录保持原样。
3. 选择“竖排右至左”，按真实正文栏数设置分栏。默认 3 栏仅适用于演示图，不适用于任意古籍。可输入从左至右的栏边界百分比，例如 `0,17,35,53,70,85,100`，首尾必须是 0 和 100。蓝线仅为预览，请检查未切到字。各栏连续覆盖全图，识别顺序从右至左、栏内从上至下；复杂版面仍须人工检查。
4. 两引擎使用相同图片、栏边界和放大倍数，默认原尺寸。单次工作画布限制 500 万像素，超过会降采样；实际裁切尺寸、是否降采样均记在结果中。Paddle 检测器内部还会按自身 960 像素长边参数调整输入，这是引擎管线的差异，并未声称其内部像素完全相同。
5. 点“同图运行两引擎×整页/分栏”，依次执行 Tesseract 整页、Tesseract 分栏、Paddle 整页、Paddle 分栏。标准稿只用于识别完成后的评分，不传给引擎。观察状态、错误、时间、CER 及原始输出，不依据汉字数量判断优劣。
6. 保存测试输入清单 JSON、全部记录 JSON 和汇总 CSV，并单独保存原始图片。每张新图建立一份测试；当前页面最多保留 10 次运行，刷新会丢失未导出的记录。CSV 用于统计，JSON 才包含完整候选和逐字对齐。

如果只校对正文，应先准备裁去标题、页码、版心的正文图；若测试整页，标准必须覆盖同页可读文字，并约定标题、正文、版心顺序，写入来源备注。不要在标准中添加图片没有的“【正文】”等标签。当前工具没有自动识别版心语义或自动排除这些区域，范围不一致会使 CER 失去解释意义。

“完成当前方法后停止”不是立即中断。Paddle 在主线程运行，推理中可能短暂卡顿；网页 90 秒单栏超时也无法强行中断同步 WASM。长图或高倍放大先裁小区域，严格桌面超时和内存采样请使用下述驱动。

## 原始输出和校对规则

- Tesseract 使用 `chi_tra_vert`，竖排 PSM 5；横排才用 PSM 6。直接保留引擎 `data.text` 和完整 TSV，跳过原网站置信度阈值替换逻辑，包括置信度为负或无效数值的候选，不把它们改成 □。
- Paddle 保留 SDK 原始 items（文本、框、分数和顺序），`textRecScoreThresh=0`。文字检测仍有必要的 DB 阈值 0.3、框阈值 0.6、扩框比 2；这不能保证所有图中文字都被检测到，也不是模型 logits 的全部候选。参数随结果保存，便于区分漏检和识别错误。
- 另存按几何阅读序排列的候选；不修改原始输出。原生顺序和几何顺序分别评分。当前几何排序只是一种坐标启发式，不能保证双行夹注、版心或行草的阅读顺序正确。
- 按 Unicode 码位逐一比较，不做 NFC/NFKC、繁简转换、异体字归并或标点补写。例如 `臺/台`、`爲/為`、`裏/裡` 分别算不同字符。扩展区汉字按一个码位计数；IVS 的变体选择符另计一个码位，因此这里是“码位 CER”，不是字形簇 CER。
- 默认仅忽略半角空格、Tab、CR/LF；全角空格、标点及变体选择符保留。也可选严格空白模式，把所有空白纳入比较。两种规则不可混作同一组结果；JSON 记录规则版本 `exact-unicode-v1`。
- 存疑原字用 □ 标记，但只要标准含 □ 或编码替代字符 U+FFFD，就整份不计 CER，不把它当通配符或偷偷剔除。未确认校对、空标准也不计。候选中的 □ 则照常作为错误字符。无法编码的异体字应另写校记，或选择有确定文字的独立裁图测试，不能擅自替代为通行字。
- `CER=(替换 S＋漏字 D＋多字 I)/标准码位数 N`，可能超过 100%。同时保留对齐正确数 `N−S−D` 和完整逐码位对齐，不能把输出总字数当正确数。重复字导致最优对齐不唯一时使用确定的对角、删除、插入优先级；对齐索引从 1 起，指去掉所选空白后的比较串，而非原文件位置。阅读顺序错误会反映在编辑距离中，没有单独可靠的“顺序错误率”。
- 对齐矩阵超过 400 万格时只保存候选、说明不计 CER，避免网页内存失控；请裁出明确小区域。失败或中途停止的方法不对部分结果评分，已完成栏和其他方法的结果保留。

## 时间与内存怎样解释

网页每种方法记录初始化时间、推理时间（包含图像准备、裁切和排序）、评分时间和方法总时间。网页四种方法依次运行并释放引擎，但模块、WASM 和文件缓存仍可能留在同一浏览器进程，不能视为四次独立冷启动。初始化和推理应分开报告，网络/磁盘缓存状态也应注明。

普通网页无法可靠读取全浏览器、Worker、WASM 的总内存峰值。若浏览器支持 `performance.memory`，页面只记录主页面 JavaScript 堆前后值，并明确标为补充信息；总峰值为 null，不会用 JS 堆冒充总内存。不支持时也是 null。

需要可比的桌面内存记录时，由维护者在 Linux、Chromium 及既有 Playwright 依赖环境运行：

```bash
cd experiments/paddle
npm run benchmark:case -- --case /path/input-case.json --image /path/scan.png --out results/qing-case-01.json
```

输入 JSON 由网页“保存测试输入清单”导出。驱动会验证图片和标准文本 SHA-256；文件不匹配则拒绝测试。每种方法新建一个桌面浏览器，在同一项目子路径、无 COOP/COEP 的条件下运行真实识别。图片字节通过本机浏览器自动化传递，不对外提供图片 URL，也没有上传识别请求。

驱动每约 100ms 读取 Chromium 进程树 `/proc/*/smaps_rollup`，记录基线、观察峰值、结束时的 PSS（按比例分摊共享页）、RSS 及私有内存。优先比较 PSS；进程树 RSS 相加会重复计算共享页。此峰值是采样观察值，可能漏掉瞬时峰值，包含浏览器自身开销，并非模型独占内存。平台不支持或读取失败时保留 null 与原因。每方法最多 180 秒，超时记录失败并关闭该浏览器，继续下一方法；每完成一项就保存 JSON，最终另存 CSV。

输入记录 `ancient-ocr-case-v1` 包含图片/标准哈希、原始标准、人工确认、来源和共同设置。结果 `ancient-ocr-comparison-v2` 还包含模型来源与哈希、实际参数、每栏框和尺寸、原生/排序候选、两种 CER、完整对齐、耗时、内存范围及错误。输入 case ID 表示同一份输入快照，每次执行另有 record ID；修改表单不会追改已保存结果。

所有推理保持免费、浏览器本地、无 API Key；首次需取得静态模型资源。私有原图、标准和结果不要提交 GitHub，尤其不要放进公开部署目录。实验目录的 models、results、dist 已忽略，但公开 docs 内手工加入的内容仍会被提交。

## 本轮验证与后续门槛

自动验收使用现代 `example.png`，只验证真实推理、四方法一致输入、精确评分、导出、故障保留、输入哈希及桌面内存采样；不是清代效果证明。可复跑：

```bash
npm test
npm run build
npm run test:case
node browser-check.mjs
```

完整现代输出会写到忽略的 `experiments/paddle/results/qa-ui-records.json` 和 `qa-desktop-pss.json`。新一轮真实清代对照应由提供者核定来源并人工校对标准，再按上述流程分别测试；保留错字、漏字和阅读顺序的人工复核记录。手机仅做过 Chromium 触屏模拟，没有 Android/iPhone 实机的稳定性或内存结论，桌面清代样本通过后再评估。模型格式、字典和许可说明继续见[实验 README](../experiments/paddle/README.md)。
